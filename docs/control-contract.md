# Контракт управления стендом (версия 1.0)

Контракт предоставляет внешнему серверному модулю доступ к **текущему статическому сетевому стенду**. В этой версии поддерживается только чтение: динамическое управление топологией пока не реализовано.

## Запуск

Команды нужно выполнять внутри контейнера `stand` либо на хосте, где доступны сетевые пространства имён стенда:

```sh
python3 /stand/scripts/control.py topology --json
python3 /stand/scripts/control.py status --json
```

Каждая команда выводит в стандартный поток вывода ровно один документ JSON. Ошибки запроса также возвращаются в формате JSON, а процесс завершается с ненулевым кодом возврата. Скрипт не исполняет произвольные команды, переданные вызывающей стороной, и не изменяет состояние сети.

## Получение топологии: `topology --json`

Ответ содержит поля `contract_version` и `topology`. Описание топологии включает постоянный идентификатор, название, состояние, перечень поддерживаемых возможностей, узлы и соединения.

У каждого узла есть:

- `id` — логический идентификатор узла;
- `namespace` — имя соответствующего сетевого пространства имён Linux;
- `role` — тип узла;
- `zone` — зона стенда, к которой относится узел;
- `overlay_ip` — адрес узла в оверлейной сети либо `null`, если адрес не назначен.

Каждое соединение содержит идентификатор `id`, список конечных точек `endpoints`, подсети `ipv4` и `ipv6` (если IPv6 для соединения задан) и тип `kind`. Конечная точка задаётся идентификатором узла `node` и именем сетевого интерфейса `interface`. Префиксы адресов соответствуют конфигурации стенда в `Makefile`.

Объект `capabilities` сообщает, какие операции действительно поддерживаются:

- `read_topology` — чтение описания топологии;
- `read_status` — получение текущего состояния;
- `create_node` — создание узла;
- `delete_node` — удаление узла;
- `change_links` — изменение соединений;
- `manage_overlay` — управление оверлейной сетью.

В этой версии `read_topology` и `read_status` имеют значение `true`. Остальные возможности имеют значение `false`: динамические изменения пока не реализованы.

## Получение состояния: `status --json`

Ответ содержит:

- `contract_version` — версия контракта;
- `observed_at` — время проверки в формате ISO 8601, в часовом поясе UTC;
- `state` — общее состояние стенда;
- `nodes` — список известных узлов с результатами проверки каждого из них.

Для каждого узла возвращаются `namespace_exists` (существует ли сетевое пространство имён), `state`, фактические сетевые интерфейсы и их адреса, полученные с помощью `iproute2`, а также сведения об интерфейсе оверлейной сети `nebula1`.

Состояние стенда `state` принимает следующие значения:

- `running` — все ожидаемые сетевые пространства имён существуют и проверка каждого из них завершилась успешно;
- `stopped` — ни одно из ожидаемых сетевых пространств имён не существует;
- `degraded` — обнаружено промежуточное состояние: часть пространств имён существует, либо проверка не дала однозначного результата.

Состояние отдельного узла может быть `running`, `stopped` или `unknown`. Состояние оверлейного интерфейса может быть `up`, `absent` либо другим значением состояния интерфейса, полученным от системы. Если сетевое пространство имён отсутствует, узел отмечается как `stopped`, а оверлейный интерфейс — как `absent`. Диагностическая информация при наличии ошибки записывается в поле `diagnostic`, а не подменяется утверждением, что всё исправно.

У каждого интерфейса указываются `name`, `state`, `mtu` и список `addresses`. Каждый адрес содержит семейство адресов `family`, сам адрес `address` и длину префикса `prefixlen`.

## Ошибки

Ошибки возвращаются в следующем формате, а процесс завершается с ненулевым кодом возврата:

```json
{
  "contract_version": "1.0",
  "error": {
    "code": "json_required",
    "message": "Укажите --json: это единственный поддерживаемый формат машинного вывода."
  }
}
```

Поле `code` предназначено для программной обработки, а `message` содержит пояснение для человека. Сейчас для запроса без флага `--json` используется код `json_required`.

## Язык и совместимость JSON-контракта

Документация, комментарии и сообщения об ошибках для пользователя написаны на русском языке. Названия полей JSON, идентификаторы, значения перечислений и коды ошибок оставлены в стабильном машинно-читаемом виде. Например, `running`, `stopped`, `degraded`, `host`, `nat`, `relay`, `lan` и `wan` — значения протокола, а не текст интерфейса. Их перевод изменил бы контракт и мог бы сломать интеграцию с серверной частью.

## Ограничения текущей версии

- Топология статическая и описана в `scripts/control.py`; сейчас она включает восемь сетевых пространств имён.
- Скрипт не создаёт и не удаляет узлы, не изменяет маршруты и не настраивает Nebula.
- Этот интерфейс командной строки — адаптер, а не HTTP-сервер. На первом этапе серверная часть может запускать его как контролируемый дочерний процесс. В дальнейшем API сможет вызывать те же функции Python напрямую, не разбирая человекочитаемый вывод `make`.
- Не передавайте интерфейсу произвольные аргументы оболочки и не публикуйте его как общедоступный HTTP-сервис с правами `root`.
- Для будущих операций изменения понадобятся строгая проверка входных данных, последовательное применение изменений и корректный откат с очисткой ресурсов при ошибках.
