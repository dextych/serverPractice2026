# Спецификация API: Управление стендом и Overlay-сетью

Данный документ описывает REST API для управления топологией стенда, жизненным циклом узлов overlay-сети, маршрутизацией и сбором метрик. Контракт служит основой для интеграции контроллера сети (Данил) и сетевой инфраструктуры стенда (Руслан).

---

## 1. Аутентификация (M2M API Token)

Аутентификация реализована по схеме **Machine-to-Machine (M2M)** через статический Bearer API-токен. 

* Заголовок для всех запросов:
  ```http
  Authorization: Bearer mesh_secret_token_2026_xyz
  ```

---

## 2. Спецификация эндпоинтов

### Группа 1: Топология и состояние сети

#### `GET /api/topology`
* **Описание:** Получение архитектурного плана сети (Blueprint).

#### `GET /api/status`
* **Описание:** Получение текущего состояния стенда (Live Health Check).

---

### Группа 2: Управление узлами

#### `POST /api/nodes`
* **Описание:** Заказ на поднятие нового узла. Вызывает старт namespace через скрипты инфраструктуры.

#### `GET /api/nodes/:id/config`
* **Описание:** Выдача конфигурации конкретному узлу (IP, ключи, маршруты). **Скрипт Руслана вызывает этот эндпоинт при старте узла**, чтобы получить свои настройки.
* **Ответ (200 OK):**
  ```json
  {
    "success": true,
    "data": {
      "overlayIp": "100.64.0.11",
      "privateKey": "...",
      "peers": ["100.64.0.1", "100.64.0.21"]
    }
  }
  ```

#### `DELETE /api/nodes/:id`
* **Описание:** Остановка узла и отзыв сертификата/ключа.

---

### Группа 3: Управление стендом и испытания сценариев отказа

#### `POST /api/stand/provision`
* **Описание:** Развертывание базовой топологии стенда одной командой.

#### `POST /api/stand/simulate/failure`
* **Описание:** Симуляция падения линка или деградации канала для проверки автоматического failover.

#### `POST /api/stand/dpi/toggle`
* **Описание:** Включение/отключение фильтрации пакетов в пространстве `ns_dpi`.

---

### Группа 4: Метрики и панель мониторинга (Чтение и Запись)

#### Эндпоинты для ИНФРАСТРУКТУРЫ (Запись данных скриптами Руслана)

#### `POST /api/metrics/telemetry`
* **Описание:** Прием данных телеметрии от скриптов-агентов на узлах.
* **Тело запроса:**
  ```json
  {
    "source": "hostA",
    "target": "relay1",
    "latencyMs": 14.2,
    "mtu": 1280
  }
  ```

#### `POST /api/metrics/events`
* **Описание:** Регистрация события о переключении маршрута (Failover).
* **Тело запроса:**
  ```json
  {
    "type": "FAILOVER",
    "description": "Основной канал заблокирован. Трафик перенаправлен через relay1."
  }
  ```

#### Эндпоинты для ВЕБ-ПАНЕЛИ (Чтение данных фронтендом Данила)

#### `GET /api/metrics/channels`
* **Описание:** Отдача состояния каналов связи и задержек для графиков.

#### `GET /api/metrics/events`
* **Описание:** Отдача истории автоматических переключений маршрутов для логов.
