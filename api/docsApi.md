# Спецификация API: Управление стендом и Overlay-сетью

Данный документ описывает REST API для управления топологией стенда, жизненным циклом узлов overlay-сети, маршрутизацией и сбором метрик. Контракт служит основой для интеграции контроллера сети (Данил) и сетевой инфраструктуры стенда (Руслан).

---

## 1. Аутентификация (M2M API Token)

В соответствии с требованиями к SDN/инфраструктурным контроллерам аутентификация реализована по схеме **Machine-to-Machine (M2M)** через статический Bearer API-токен (API Key). 

* Пользовательские аккаунты, сессии и регистрация отсутствуют.
* Токен генерируется администратором стенда и задается в конфигурации окружения (`.env`):
  ```env
  API_SECRET_TOKEN=mesh_secret_token_2026_xyz
  ```
* Все запросы к мутирующим или защищенным эндпоинтам обязаны передавать заголовок:
  ```http
  Authorization: Bearer mesh_secret_token_2026_xyz
  ```
* При отсутствии заголовка или несовпадении значения сервер возвращает статус **`401 Unauthorized`**.

## 2. Базовые форматы обмена данными

### 2.1. Успешный ответ
```json
{
  "success": true,
  "data": { ... }
}
```

### 2.2. Ошибка
```json
{
  "success": false,
  "error": {
    "code": "ERROR_CODE",
    "message": "Человекочитаемое описание ошибки",
    "details": []
  }
}
```

### 2.3. HTTP-статусы
* **200 OK**: Запрос успешно выполнен.
* **201 Created**: Узел или маршрут успешно создан и активирован.
* **400 Bad Request**: Некорректные параметры запроса.
* **401 Unauthorized**: Отсутствует или недействителен токен `Authorization: Bearer ...`.
* **404 Not Found**: Запрашиваемый ресурс не найден.
* **500 Internal Server Error**: Ошибка выполнения внутреннего кода контроллера.
* **502 Bad Gateway**: Сбой взаимодействия с инфраструктурой стенда (скриптами `control.py`).

## 3. Спецификация эндпоинтов

### Группа 1: Топология и состояние сети

Эндпоинты для получения информации о структуре сети и её текущем "здоровье".

#### `GET /api/topology`
* **Описание:** Получение архитектурного плана сети. Возвращает список всех участников, их подсети и статические связи (links) через NAT и DPI.
* **Заголовки:** `Authorization: Bearer <token>`
* **Ответ (200 OK):** Возвращает JSON-структуру с полями `nodes` и `links`.

#### `GET /api/status`
* **Описание:** Получение текущего состояния стенда (Live Health Check). Возвращает живой статус сетевых пространств имен (namespaces), интерфейсов и оверлея (например, Nebula).
* **Заголовки:** `Authorization: Bearer <token>`
* **Ответ (200 OK):** Возвращает JSON со статусом узлов (`running` / `stopped`) и диагностическими сообщениями.

---

### Группа 2: Управление узлами (Поднятие строго через API)

Узлы запрещено поднимать ручным вмешательством в инфраструктуру. Контроллер управляет процессом.

#### `POST /api/nodes`
* **Описание:** Заказ на поднятие нового узла. Вызывает выделение IP, выписку ключей и старт namespace через скрипты инфраструктуры.
* **Заголовки:** `Authorization: Bearer <token>`
* **Тело запроса:**
  ```json
  {
    "name": "hostC",
    "role": "edge",
    "zone": "zone-natB",
    "transport": "amnezia_wg"
  }
  ```
* **Ответ (201 Created):** Данные созданного узла (IP в оверлее, статус, публичный ключ).

#### `DELETE /api/nodes/:id`
* **Описание:** Остановка узла, отзыв сертификата/ключа и перевыпуск таблицы маршрутов для остальных участников.
* **Заголовки:** `Authorization: Bearer <token>`
* **Ответ (200 OK):** Сообщение об успешном удалении.

---

### Группа 3: Управление стендом и испытания сценариев отказа

Эндпоинты для инициализации стенда, симуляции сбоев и управления фильтрацией пакетов.

#### `POST /api/stand/provision`
* **Описание:** Развертывание базовой топологии стенда одной командой.
* **Заголовки:** `Authorization: Bearer <token>`
* **Тело запроса:**
  ```json
  {
    "roles": ["hostA", "hostB", "relay1", "relay2", "dpi"],
    "natType": "symmetric",
    "dpiEnabled": true
  }
  ```

#### `POST /api/stand/simulate/failure`
* **Описание:** Симуляция падения линка или деградации канала для проверки автоматического failover.
* **Заголовки:** `Authorization: Bearer <token>`
* **Тело запроса:**
  ```json
  {
    "targetNode": "relay1",
    "action": "link_down" // "link_down" | "packet_loss_100" | "throttle"
  }
  ```

#### `POST /api/stand/dpi/toggle`
* **Описание:** Включение/отключение фильтрации пакетов в пространстве `ns_dpi` для проверки обфусцированного транспорта.
* **Заголовки:** `Authorization: Bearer <token>`
* **Тело запроса:** `{"enabled": true}`

---

### Группа 4: Метрики и панель мониторинга (Чтение и Запись)

#### Эндпоинты для инфраструктуры

#### `POST /api/metrics/telemetry`
* **Описание:** Прием данных телеметрии от скриптов-агентов на узлах.
* **Тело запроса:**
  ```json
  {
    "source": "hostA",
    "target": "relay1",
    "latencyMs": 14.2,
    "mtu": 1280
  }
  ```

#### `POST /api/metrics/events`
* **Описание:** Прием логов. Стенд отправляет уведомление, когда маршрут переключился.
* **Тело запроса:**
  ```json
  {
    "type": "FAILOVER",
    "description": "Основной канал заблокирован. Трафик перенаправлен через relay1."
  }
  ```

#### Эндпоинты для веб-панели

#### `GET /api/metrics/channels`
* **Описание:** Отдача состояния каналов связи и задержек для графиков.

#### `GET /api/metrics/events`
* **Описание:** Отдача истории автоматических переключений маршрутов для логов.
